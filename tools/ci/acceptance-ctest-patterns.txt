# Test-name patterns the M5 product-acceptance focused-behavior gate runs.

# One pattern per line; blank lines and #-comments ignored. The gate combines
# them into one alternation for `ctest -R`, AND asserts each one matches at
# least one registered test. Three patterns in the previous inline alternation
# matched NOTHING and nobody noticed, because a zero-match alternative inside a
# big `(a|b|c)` is silent -- ctest still runs the other alternatives and
# reports success. The tests behind them had therefore never run in CI:
#
#   ^#34:          -> catch_discover_tests registers these names WITH literal
#   ^#34 bridge       quotes, so the name starts with '"', not '#'. 12 tests.
#   ^native:<space> -> TEST_PREFIX is "native:" with no trailing space. 1 test.
#
# The quote-tolerant '^"?' prefix below survives either registration style.

# An LFO must not move a mute the user authored: the four Catch2 cases behind

# Two of the four are CONTROLS that stay green on the broken revision too (an

^"?authored mute:

# The same invariant proved end to end through `Spectr::process`, which is the
# only place the two halves meet: the audio path re-derives the morph per block
# while the control worker applies it only on change, and the published field
# it hands the editor IS the field the DSP renders. The unit cases above cannot
# see that gap -- they call `apply_internal_modulation` directly, and it passed
# them while a muted band still measured -6 dB and linear gain 0.50 in a real
# render. Nothing else here matches the name.
^"?a band muted after both snapshots

# The POSITIVE CONTROL for that gate, and it earned its own line twice over.
# Refusing to derive the field until the control worker says it did is
# trivially satisfied by never deriving it, which the muted-band case above
# cannot see -- a plant that disabled the derivation outright left it green.
# The control also has to pick values a default field cannot imitate: at
# -6/+6 the midpoint is 0 dB, which is what an underived field already reads,
# so the first version of it could not fail either.
^"?a derived morph still reaches

# The same defect reached by dragging morph FIRST. Once the field is derived
# the gate is open and the audio thread rebuilds it from the bank every block,
# so an edit made after the drag is reverted unless the sparse overrides are
# replayed. The ungated case above cannot see this path -- with the replay
# removed it stays green while the band returns at 0.48 linear gain.
^"?a band muted after a derived morph

# The band context menu's unmute, and its negative control. This one needs its
# own pattern because it is the only gate in the suite that reads a LEVEL

# and state-flag row in this gate stays green while the user's work is lost.
# It reports 77 (CTest "Not Run") when the pinned SDK carries no context-menu
# handler, so a pin that cannot reach the menu is visible rather than silent.
^Spectr-band-menu-unmute-restores
