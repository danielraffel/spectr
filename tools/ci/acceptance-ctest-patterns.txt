# Test-name patterns the M5 product-acceptance focused-behavior gate runs.
#
# One pattern per line; blank lines and #-comments ignored. The gate combines
# them into one alternation for `ctest -R`, AND asserts each one matches at
# least one registered test. Three patterns in the previous inline alternation
# matched NOTHING and nobody noticed, because a zero-match alternative inside a
# big `(a|b|c)` is silent -- ctest still runs the other alternatives and
# reports success. The tests behind them had therefore never run in CI:
#
#   ^#34:          -> catch_discover_tests registers these names WITH literal
#   ^#34 bridge       quotes, so the name starts with '"', not '#'. 12 tests.
#   ^native:<space> -> TEST_PREFIX is "native:" with no trailing space. 1 test.
#
# The quote-tolerant '^"?' prefix below survives either registration style.
^"?#34:
^"?#34 bridge

# The AU artifact case run with the parameter-adoption worker held back, so
# it can only pass if a plain parameter WRITE reaches the DSP without that
# thread. The plain run of the same case lives under `^Pulp host loads`, which
# the workflow runs separately.
^Spectr-au-param-write-without-sync-worker

# The additive-marquee suite and its three controls. `materialized` above
# would match them, but it also matches a dozen other rows, so it can never
# report their absence -- and they registered under the browser oracle's
# node+chrome guard once already, where a chrome-less runner would have
# dropped all four in silence.
^Spectr-materialized-additive-marquee

# The SHORTCUTS panel's no-wrap gates. The budget half needs no binary; the
# rendered half opens the panel in the shipping native editor. Both are named
# outside the `materialized` pattern above, so without this line they register
# and never run -- which is the exact failure this file was written after.
^Spectr-shortcut-panel

# The browser oracle lane registers its tests only when BOTH node and chrome
# are found (CMakeLists.txt guards them, and CMake warns when disabled). The
# acceptance runner has no chrome, so these are UNMEASURED there -- reported
# every run, never silently passed.
optional(browser oracle lane needs node+chrome): ^Spectr-browser-

# The product-icon artifact gate and its two plant controls. Nothing else here
# matches the name, so without this line all three register and never run --
# which would make a gate written to catch a silently-missing icon itself a
# silently-dead check. The acceptance build already produces all four bundles
# (Spectr_Standalone / _AU / _VST3 / _CLAP), so the gate has something to read;
# were that to change it exits 3 rather than passing on an empty measurement.
^Spectr-bundle-icons
# One-press dropdown switching and its scoping control. Neither is matched by
# `^every native dropdown` or `^native ...` above -- they start with the verb,
# not with "native" -- so without these two lines they register and never run,
# which is measurable: the acceptance alternation selected 75 tests and 0 of
# these 2.
^"?switching native dropdowns
^"?dismissing a native dropdown
